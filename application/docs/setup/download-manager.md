# B-Fabric Documentation

## Download Manager

This page contains the guide for installing/configuring the B-Fabric Download Manager.

For setting up your development environment, this Download Manager setup is not required (until you have to work on this topic)!

Since the Download Manager is a Java Rich Internet Application (RIA), it is necessary to install Java Web Start in order to run RIA executable files locally. Java Web Start is already included in the
Java Runtime Environment (JRE) since release of Java 5.0. However, it is still good idea to check whether it runs.

```
 javaws url_of_jnlp
```

Download Manager accesses to several storages, in which raw data and metadata files are stored. Authentication is done by using Single sign-on (SSO).

The Download Manager needs an authentication ticket in order to communicate with an SSO server. The ticket is generated by mkpubtkt.sh script. This script is available under downloadmanager/src/misc
directory. It is important to copy this script to a local path in order to avoid conflicts with svn changes. Then new local path must be specified with system property pubtktGeneratorFilePath in
B-Fabric. The generator script uses tkt_privkey_dsa.pem file as well in order to generate single use credentials.

In addition to several external storages, the Download Manager needs two internal storages in order to store whole upload files; i.e. attachment files, local import files, project description and
report files, etc. These storages must be SSO servers. Then, newly created local storages have to be registered in B-Fabric as Storage entity with names '
Local Internal Storage' and 'Local External Storage' respectively. Then the final step is to register DM type Access entities for the associated Storages entities.

Note: In Project download, a xml file that keeps entire metadata of the given project is generated automatically for the download. Project xml files are stored in the Local Internal Storage for
limited amount of time. After the expiration date (24 hours), the DeleteExpiredXmls job seeks for the expired xml files and deletes them.
